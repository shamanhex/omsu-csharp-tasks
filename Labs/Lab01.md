# Разработка калькулятора

Необходимо доработать консольное приложение в проекте `src/Labs`. Приложение работает только в неинтерактивном режиме: интерактивное меню отсутствует, все данные передаются через аргументы командной строки.

## Аргументы командной строки

| Аргумент | Описание                                                |
| -------- | ------------------------------------------------------- |
| `--task` | номер выполняемого задания (заменяет номер пункта меню) |
| `-x`     | целочисленный параметр X                                |
| `-y`     | целочисленный параметр Y                                |
| `-z`     | целочисленный параметр Z                                |

Аргументы могут указываться в любом порядке. В рамках данной лабораторной работы реализуется только задание `--task 1` — расчёт формулы.

## Базовые требования

1. Приложение должно находиться в проекте `src/Labs` и представлять собой единое консольное приложение (в дальнейшем оно дорабатывается в рамках последующих лабораторных работ).
2. При запуске без аргументов на экран выводится справка. Первая строка справки должна начинаться с `HELP:`, далее — текст в свободной форме, описывающий режимы работы и аргументы.
3. Аргумент `--task` задаёт номер выполняемого задания (заменяет номер пункта меню). В рамках данной работы реализуется задание `--task 1` — расчёт формулы.
4. Параметры X, Y, Z передаются аргументами `-x`, `-y`, `-z` и имеют целочисленный тип.
5. Расчётная формула выдаётся индивидуально (см. раздел «Формулы»).
6. Результат расчёта выводится строкой, начинающейся с `RESULT:`; значение форматируется до 3 знаков после запятой (пример: `1.004`).
7. Все входные аргументы должны контролироваться на корректность и непротиворечивость (деление на 0 невозможно, квадратный корень из отрицательного числа не является вещественным и пр.). При ошибке выводится строка, начинающаяся с `ERROR:`, с пояснением; программа завершается, не запрашивая значение повторно.
8. Вывод `NaN` или аварийное завершение программы при корректных входных данных — незачёт.
9. Должна осуществляться проверка на заведомо некорректные значения («проверка на дурака»): нечисловые строки и пр. должны приводить к выводу сообщения об ошибке, начинающегося с `ERROR:`.

## Формулы по вариантам

```
1. (X+Y)/Z+sqrt(X)
2. X/Z+Y^2
3. Z^2+7+sqrt(X)
4. Y^2+3*sqrt(X)+Z
5. (Y-sqrt(X))/Z
6. Y+sqrt(X % Z)
7. X % Z+sqrt(Y)
8. sqrt(X)-6/Z
9. Z/X + 7*sqrt(Y)
10. (X+sqrt(Y)) / Z
11. (X+sqrt(Y)) % Z
12. X % Z + sqrt(Y)
13. X*Y % Z
14. (Y % X)/sqrt(Z)
15. (Y - X)/sqrt(Z)
```

## Приёмка

### Критерии автоматизированной приёмки

Автоматизированный контроль анализирует только первую строку вывода:

- Вывод справки начинается со строки `HELP:`.
- Вывод результата расчёта начинается со строки `RESULT:`.
- Вывод ошибки начинается со строки `ERROR:`.
- Пустые строки в начале вывода игнорируются. Анализируется первая непустая строка.
- Всё, что выводится после первой строки, при анализе успешности игнорируется.

### Приёмка

#### Запуск без аргументов

```
.\Labs.exe
HELP:
    --task - task number
    -x - value of X
    -y - value of Y
    -z - value of Z
    ...
```

#### Ввод числа вне диапазона. 

Программа должна выходить с ошибкой, если --task меньше 1 или больше 1

```
.\Labs.exe --task 2 -x 1 -y 2 -z -1
ERROR: Unknown task. Task number must not exceed 1.
```
```
.\Labs.exe --task 0 -x 1 -y 2 -z -1
ERROR: Unknown task. Task number cannot be less than 1.
```

#### Ввод некорректного числа

Программа должна выходить с ошибкой, если --task не является целым числом

```
.\Labs.exe --task one -x 1 -y 2 -z -1
ERROR: Task number must be integer number.
```
```
.\Labs.exe --task 1.0 -x 1 -y 2 -z -1
ERROR: Task number must be an integer.
```

#### Некорректное значение параметра

```
.\Labs.exe --task 1 -x Zero -y 2 -z 3
ERROR: Value X must be an integer.
```

#### Успешный запуск калькулятора

```
.\Labs.exe --task 1 -x 1 -y 2 -z 3
RESULT: 1.004
```

#### Некорректный аргумент при запуске

```
.\Labs.exe --task 1 -x 1 -y 2 -z -1
ERROR: Value Z must be greater than 0.
```

## Примечания

Для данного задания приёмка кода не выполняется! Претензии по оформлению кода значимыми не являются и на зачёт задания не влияют.
