# Работа со строками

Необходимо доработать консольное приложение в проекте `src/Labs`. Приложение работает только в неинтерактивном режиме: интерактивное меню отсутствует, все данные передаются через аргументы командной строки.

## Аргументы командной строки

| Аргумент | Описание               |
| -------- | ---------------------- |
| `--task` | номер выполняемого задания |
| `-s1`    | первая строка           |
| `-s2`    | вторая строка           |

Аргументы могут указываться в любом порядке. В рамках данной лабораторной работы реализуется задание `--task 3` — проверка строк. Задания `--task 1` и `--task 2` реализованы в предыдущих лабораторных работах и должны продолжать работать.

## Базовые требования

1. Приложение должно находиться в проекте `src/Labs` и представлять собой единое консольное приложение (в дальнейшем оно дорабатывается в рамках последующих лабораторных работ).
2. При запуске без аргументов на экран выводится справка. Первая строка справки должна начинаться с `HELP:`, далее — текст в свободной форме, описывающий режимы работы и аргументы.
3. Аргумент `--task` задаёт номер выполняемого задания. Допустимые значения — `1`, `2` и `3`.
4. Строки передаются аргументами `-s1` (первая строка) и `-s2` (вторая строка). Аргументы `-s1` и `-s2` обязательны.
5. Для двух строк выполняются и выводятся 4 проверки (см. раздел «Проверки»).
6. Проверка принадлежности строки типам email / телефон / IP-адрес выполняется с помощью регулярных выражений (RegEx).
7. Результат каждой проверки выводится отдельной строкой вида `<МЕТКА>: <TRUE|FALSE>` (точный формат — в разделе «Приёмка»).
8. Все входные аргументы должны контролироваться на корректность: `--task` должен быть целым числом в диапазоне 1–3, аргументы `-s1` и `-s2` обязательны. При ошибке выводится строка, начинающаяся с `ERROR:`, с пояснением; программа завершается, не запрашивая значение повторно.
9. Аварийное завершение программы при корректных входных данных — незачёт.
10. Должна осуществляться проверка на заведомо некорректные значения («проверка на дурака»): отсутствие обязательных аргументов, некорректный `--task` и пр. должны приводить к выводу сообщения об ошибке, начинающегося с `ERROR:`.
11. Код должен быть оформлен в соответствии с требованиями:
    - Отступы
    - 1 строка — 1 оператор
    - Каждая проверка строк — отдельный метод
    - Каждое задание (`--task`) — отдельный метод
    - Выбор задания (`--task`) реализовать через `switch`
    - Разбор аргументов командной строки и вывод результатов — отдельные методы
    - Методы проверки строк не читают данные из консоли или аргументов, а принимают строки параметрами и возвращают результат
    - Имена переменных — осмысленные (в идеале венгерская нотация: [https://ru.wikipedia.org/wiki/%D0%92%D0%B5%D0%BD%D0%B3%D0%B5%D1%80%D1%81%D0%BA%D0%B0%D1%8F_%D0%BD%D0%BE%D1%82%D0%B0%D1%86%D0%B8%D1%8F])

## Проверки

Для двух переданных строк выполняются следующие проверки:

1. **Построчное совпадение (EQUAL)** — строки совпадают посимвольно (с учётом регистра).
2. **Совпадение после нормализации (NORMALIZED)** — строки совпадают, если привести их к одному регистру, удалить пробельные символы в начале и в конце, а любую последовательность из двух и более подряд идущих пробельных символов заменить одним пробелом.
3. **Перевёртыш (REVERSED)** — первая строка является перевёртышем второй (символы первой строки идут в обратном порядке относительно второй).
4. **Проверка типов** — для каждой строки определяется, является ли она email-адресом, телефонным номером или IP-адресом.

## Использование RegEx для проверки шаблона

Для проверки шаблона email, IP-адреса или телефонного номера следует использовать RegEx:

```
RegEx для Email:    [^@ \t\r\n]+@[^@ \t\r\n]+\.[^@ \t\r\n]+
RegEx для IPv4:     (\b25[0-5]|\b2[0-4][0-9]|\b[01]?[0-9][0-9]?)(\.(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)){3}
RegEx для Телефона: ^[\+]?[(]?[0-9]{3}[)]?[-\s\.]?[0-9]{3}[-\s\.]?[0-9]{4,6}$
```

Шаблон должен применяться ко всей строке целиком (полное совпадение); при необходимости шаблон следует заякорить якорями `^` и `$`.

Больше примеров regex можно найти на сайте: <https://ihateregex.io/>

## Приёмка

### Критерии автоматизированной приёмки

Автоматизированный контроль анализирует только первые строки вывода:

- Вывод справки начинается со строки `HELP:`.
- При успешном расчёте первая значимая строка начинается с `EQUAL:`, далее следуют строки `NORMALIZED:`, `REVERSED:`, `S1_EMAIL:`, `S1_PHONE:`, `S1_IP:`, `S2_EMAIL:`, `S2_PHONE:`, `S2_IP:`.
- Вывод ошибки начинается со строки `ERROR:`.
- Значение каждой проверки — `TRUE` или `FALSE` (верхний регистр).
- Пустые строки в начале вывода игнорируются.
- Всё, что выводится после проверяемых строк, при анализе успешности игнорируется.

### Запуск без аргументов

```
.\Labs.exe
HELP:
    --task - task number
    -s1 - first string
    -s2 - second string
    ...
```

### Ввод числа вне диапазона

Программа должна выходить с ошибкой, если `--task` меньше 1 или больше 3:

```
.\Labs.exe --task 4 -s1 abc -s2 abc
ERROR: Unknown task. Task number must not exceed 3.
```
```
.\Labs.exe --task 0 -s1 abc -s2 abc
ERROR: Unknown task. Task number cannot be less than 1.
```

### Ввод некорректного числа

Программа должна выходить с ошибкой, если `--task` не является целым числом:

```
.\Labs.exe --task three -s1 abc -s2 abc
ERROR: Task number must be an integer.
```
```
.\Labs.exe --task 3.0 -s1 abc -s2 abc
ERROR: Task number must be an integer.
```

### Отсутствие обязательного аргумента

Программа должна выходить с ошибкой, если не указан один из обязательных аргументов `-s1` или `-s2`:

```
.\Labs.exe --task 3 -s1 abc
ERROR: Value S2 must be specified.
```
```
.\Labs.exe --task 3 -s2 abc
ERROR: Value S1 must be specified.
```

### Успешный запуск: посимвольное совпадение

```
.\Labs.exe --task 3 -s1 "Hello, world!" -s2 "Hello, world!"
EQUAL: TRUE
NORMALIZED: TRUE
REVERSED: FALSE
S1_EMAIL: FALSE
S1_PHONE: FALSE
S1_IP: FALSE
S2_EMAIL: FALSE
S2_PHONE: FALSE
S2_IP: FALSE
```

```
.\Labs.exe --task 3 -s1 "  Hello   world  " -s2 "hello world"
EQUAL: FALSE
NORMALIZED: TRUE
REVERSED: FALSE
S1_EMAIL: FALSE
S1_PHONE: FALSE
S1_IP: FALSE
S2_EMAIL: FALSE
S2_PHONE: FALSE
S2_IP: FALSE
```
