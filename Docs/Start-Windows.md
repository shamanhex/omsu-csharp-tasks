# Старт с нуля: Windows

Инструкция проходится **один раз** сверху вниз. Команды копируйте целиком и вставляйте в терминал (правая кнопка мыши или `Ctrl+V`), затем нажимайте `Enter`.

Другие ОС: [Linux](./Start-Linux.md) · [macOS](./Start-macOS.md)

## Шаг 0. Откройте терминал PowerShell

Нажмите `Win`, наберите `PowerShell` и откройте **Windows PowerShell** (или **Терминал**).

Появится окно со строкой вида:

```
PS C:\Users\ivanov>
```

`PS` в начале означает, что вы в PowerShell. Все команды ниже вводятся здесь.

> Не используйте «Командную строку» (`cmd`) — в ней часть команд не работает.

## Шаг 1. Проверьте, что всё установлено

Выполните по очереди три команды:

```powershell
git --version
```

```powershell
dotnet --list-sdks
```

```powershell
$PSVersionTable.PSVersion
```

Правильный результат:

| Команда | Что должно быть | Пример |
|---|---|---|
| `git --version` | любая версия | `git version 2.47.1.windows.2` |
| `dotnet --list-sdks` | **есть строка, начинающаяся с `10.`** | `10.0.103 [C:\Program Files\dotnet\sdk]` |
| `$PSVersionTable.PSVersion` | 5.1 или выше | `5  1  26100  ...` |

PowerShell в Windows уже встроен, ставить его не нужно.

### Если чего-то нет

Сообщение `... не распознано как имя командлета` (или `is not recognized`) означает, что программа не установлена. Установите её одной из команд:

```powershell
winget install --id Git.Git -e
```

```powershell
winget install --id Microsoft.DotNet.SDK.10 -e
```

Если `winget` тоже не найден — скачайте установщики вручную и ставьте с настройками по умолчанию (кнопка «Next» до конца):

- Git: <https://git-scm.com/download/win>
- .NET SDK 10.0: <https://dotnet.microsoft.com/download/dotnet/10.0> (столбец **SDK**, установщик **x64**)

> **Важно:** после установки **закройте окно PowerShell и откройте новое**, иначе новые команды не будут видны. Затем повторите Шаг 1.

Если в `dotnet --list-sdks` есть только 8.0 или 9.0 — это не подходит, нужен именно 10.0 (старые версии можно не удалять).

## Шаг 2. Разрешите запуск скриптов PowerShell

По умолчанию Windows запрещает запускать `.ps1`-скрипты, а автотесты написаны именно так. Снимите запрет для своего пользователя (права администратора не нужны):

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy Unrestricted
```

Если появится вопрос о подтверждении — введите `Y` и нажмите `Enter`.

Проверка:

```powershell
Get-ExecutionPolicy
```

Должно быть напечатано `Unrestricted`. Делается один раз на компьютере.

## Шаг 3. Скачайте проект

Перейдите в домашнюю папку и скачайте репозиторий:

```powershell
cd ~
git clone https://github.com/shamanhex/omsu-csharp-tasks.git
```

Появится папка `C:\Users\<ваше имя>\omsu-csharp-tasks`. Её можно открыть в Проводнике командой `explorer .\omsu-csharp-tasks`.

> Ошибка `destination path 'omsu-csharp-tasks' already exists` значит, что проект уже скачан. Повторно клонировать не нужно — переходите к Шагу 4.

## Шаг 4. Перейдите в папку проекта

```powershell
cd ~/omsu-csharp-tasks/src/Labs
```

Строка приглашения изменится на `PS C:\Users\ivanov\omsu-csharp-tasks\src\Labs>`. **Все следующие команды выполняются из этой папки.**

Когда вы откроете новое окно PowerShell (например, на следующий день), начинайте именно с этой команды.

## Шаг 5. Соберите проект

```powershell
dotnet build
```

Первая сборка может занять до минуты. В конце должно быть написано `Build succeeded` (или `Сборка успешно завершена`) и `0 Error(s)`.

Если есть строки с `error CS....` — в коде ошибка, текст подсказывает файл и номер строки.

Собранная программа лежит здесь: `bin\Debug\net10.0\Labs.exe`.

**После каждого изменения кода запускайте `dotnet build` заново**, иначе запустится старая версия программы.

## Шаг 6. Запустите программу

Без аргументов:

```powershell
.\bin\Debug\net10.0\Labs.exe
```

С аргументами (пример для Lab01):

```powershell
.\bin\Debug\net10.0\Labs.exe --task 1 -x 1 -y 2 -z 3
```

Для исходного шаблона проекта результат будет таким:

```
HELP: No help, life is hard!
```

> Точка и обратный слеш `.\` в начале обязательны: так PowerShell понимает, что программу надо искать в текущей папке.

Альтернатива — собрать и запустить одной командой (аргументы программы пишутся после `--`):

```powershell
dotnet run -- --task 1 -x 1 -y 2 -z 3
```

## Шаг 7. Запустите автотесты

Сначала обязательно выполните `dotnet build` (Шаг 5). Затем:

```powershell
..\UAT.Labs\RunCheckLab01.ps1 -Variant 1
```

Вместо `1` укажите **свой** номер варианта. Если `-Variant` не указать, скрипт спросит его сам.

Для других лабораторных меняется только номер в имени скрипта: `RunCheckLab02.ps1`, `RunCheckLab03.ps1` и т.д.

### Как читать результат

```
TEST [OK]: Запуск без аргументов
    CMD: .\src\Labs\bin\Debug\net10.0\Labs.exe
    OUTPUT: HELP: No help, life is hard!

TEST [ERR]: Ввод числа вне диапазона [--task 2]
    CMD: .\src\Labs\bin\Debug\net10.0\Labs.exe --task 2 -x 1 -y 2 -z -1
    ACTUAL: HELP: No help, life is hard!
    EXPECTED: ERROR: Unknown task. Task number must not exceed 1.
    COMMENT: Ожидалась ошибка (первая строка должна начинаться с 'ERROR'), ...
...
Итог: OK: 1, ERR: 10, WARN: 0
```

- `[OK]` — тест пройден.
- `[ERR]` — тест не пройден. Сравните `ACTUAL` (что вывела ваша программа) и `EXPECTED` (что ожидалось), прочитайте `COMMENT`.
- `[WARN]` — программа не завершилась за 5 секунд. Чаще всего в конце стоит `Console.ReadKey()` / `Console.ReadLine()` — уберите их.
- `CMD` — точная команда запуска. Её можно выполнить вручную (Шаг 6), чтобы посмотреть на поведение программы.

На пустом шаблоне почти все тесты падают — это нормально, их и нужно «починить» своей реализацией. Лабораторная готова, когда `ERR: 0`.

## Частые проблемы

| Сообщение | Что делать |
|---|---|
| `... не распознано как имя командлета ...` / `is not recognized ...` | Программа не установлена или окно открыто до установки. См. Шаг 1, откройте новое окно PowerShell. |
| `... не может быть загружен, так как выполнение сценариев отключено в этой системе` | Не выполнен Шаг 2. |
| `MSBUILD : error MSB1003: Specify a project or solution file` | Вы не в той папке. Выполните `cd ~/omsu-csharp-tasks/src/Labs`. |
| `NETSDK1045: The current .NET SDK does not support targeting .NET 10.0` | Установлен старый .NET SDK. Установите 10.0 (Шаг 1). |
| `Ошибка: исполняемый файл не найден.` (в автотесте) | Не выполнена сборка. Запустите `dotnet build`. |
| `The process cannot access the file ... Labs.exe because it is being used by another process` | Программа ещё запущена (например, в Visual Studio или другом окне). Закройте её и повторите `dotnet build`. |
| Проверить, в какой папке вы сейчас находитесь | Команда `pwd`. |
